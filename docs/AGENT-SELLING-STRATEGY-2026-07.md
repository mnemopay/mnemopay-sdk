## MnemoPay Is Not the Product — It's the Trust Layer

| | MnemoPay | AI agent |
|---|---|---|
| What | Governance: budgets, permissions, audit receipts, memory | Autonomous loop that **does work** |
| Analogy | Card + compliance log + spending rules | Employee who uses the card |
| Buyer | Developers / platform teams | Business owners who want an **outcome** |

The next wave sells **named workers for specific jobs** with guardrails and a bill. MnemoPay makes those workers trustworthy in regulated contexts.

## Market Signal (mid-2026)

1. Vertical outcome agents — "files HMO claims," not "answers questions"
2. Bounded autonomy — fixed permissions, human approval on money/deploy/install
3. Audit trail — healthcare, fintech, EU AI Act
4. Outcome pricing — per claim, per intake, per reconciliation run

## Agents To Sell (ranked)

### 1. WellBeing hospital agents (lead SKU)

| Agent | Job |
|-------|-----|
| Claims Prep Agent | HMO checklists, denial-risk, submission packets |
| Intake Summary Agent | Notes → doctor-ready summary (English/Pidgin) |
| Queue Coordinator Agent | Flow, WhatsApp updates, wall board |

Pilot: Lagos hospitals. Demo: https://wellbeing-production.up.railway.app

MnemoPay value: Article 12 audit for "what did the AI change in this visit record?"

### 2. Auditable coding agent (MnemoPay IDE)

Sell to regulated eng teams — healthcare IT, fintech, legal, gov. Hosted runs with receipts, not npm downloads.

### 3. Fintech ops agents (Dele + MnemoPay)

Reconciliation Agent, Float Watch Agent. Nigeria-specific.

### 4. Creator Publish Agent (deprioritize)

JKAI demo material only.

### 5. AgentBnB skills (after vertical proof)

List claims prep, intake, reconciliation skills once standalone agents work.

## Do NOT Sell

- Generic BizSuite AI
- MnemoPay SDK to non-developers as the SKU
- Open-ended do-anything agents
- Crypto agent kits

## Positioning

> Hospital and fintech agents that do one job, stay inside a budget, and leave an audit trail.
